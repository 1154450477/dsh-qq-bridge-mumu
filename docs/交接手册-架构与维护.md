# 交接手册 — 架构与维护（dsh-qq-bridge-mumu）

> 写给下一个接手维护这个仓库的人。读完这一份就能独立改代码、发版、排障。
> 依据版本 **0.5.2**（commit `9996613`，2026-10-25）核对；文中所有 `file:line` 都按当前工作区源码逐一核对过。

---

## 一、项目定位与设计哲学

**定位**：一个 DSH（DeepSeek Harness）bundle 插件，让 DSH 里的 AI 伙伴和 QQ 双向互通——伙伴在目标会话里说完一整轮，最后一句自动发到 QQ；你在 QQ 里说的话自动转进 DSH 开一轮。附带 `mumu-mcp/`：把 MuMu 模拟器里的安卓机变成 MCP 工具，让伙伴能真的"玩手机"，玩的时候 QQ 消息不丢。

**设计哲学**（每一条都能在代码里找到对应）：

1. **安全默认**：总开关关、试运行开（`lib/host.js:32-33`）。不手动打开，一句都不会真的发到 QQ。
2. **配置在用户目录，不在代码里**：`~/.dsh/qq-bridge-config.json`（`lib/host.js:26`）。卸载重装不丢设置。每次都现读（`读配置()`，host.js:233），所以改配置文件**热生效**，不用重启。
3. **能自己修的不留坑**：会话 id 两种写法统一归一（`会话键()`，host.js:127）；路由改名不改 client.js 而是双前缀兜底（0.5.1）；GIF 被转码就自己记一张"原图反查表"（host.js:139）。
4. **消息像人**：拆气泡（40 字上限，host.js:381）、按句读打字间隔（host.js:443）、连发消息凑一批再转（防抖 3 秒）、回复只发一轮的最后一句。
5. **手机模式"消息永不丢"**：她在玩手机 ≠ 没看见——所有收消息路径统一过 `转一批()` 漏斗（host.js:1199）：在玩→挂起+回执；喊停→关机+steer 原话；暂停→不关机。
6. **中文命名 + 测试可脱离宿主跑**：函数全中文（`转入一条`、`转一批`），三套测试用假 ctx/假 fetch，`node tests/宿主半边.mjs` 不装插件不连 QQ 就能跑。

## 三、完整架构与数据流

### 3.1 链路总览

```
QQ ←→ SnowLuma/NapCat (OneBot 11)
        HTTP 3000（发消息 + 历史轮询兜底）
        WS   3001（实时推送，主路，~0.1s）
      ←→ dsh-qq-bridge-mumu (DSH 插件，宿主进程内)
        MuMu 控制口 127.0.0.1:8791（mumu-mcp：手机模式/pending/exit）
      ←→ DSH agent（followup / steer / cancel + session/event 监听）
      ←→ 设置页 http://127.0.0.1:3080（/dsh-qq-bridge/* 双前缀路由）
```

### 3.2 DSH → QQ（伙伴说话 → QQ）

1. `ctx.on('session/event')` 挂监听（host.js:1377）→ `收到事件()`（host.js:734）。
2. `assistant/message`（host.js:739）：`interrupted` 就清空本轮（host.js:742）；否则记 `最后活动时间`，若本轮已出正文/图则置 `本轮已吭声=true` 并撤掉超时提醒定时器（host.js:750-757）。正文记进 `上一轮`（只记最后一句；图可先于字到达，先攒着，host.js:758-762）。
3. `turn/end` 且 `reason.kind === 'completed'`（host.js:795）：`上一轮.轮号 === d.turn` 且没发过（`已发轮` Set 去重）→ `落地一发()`（host.js:567）。
4. `落地一发`：目标会话没填/已归档/总开关关 → 记账不转；试运行开 → 只记账（host.js:581）。
5. `发到QQ()`（host.js:491）：若发图开着，先 `抠正文图()`（host.js:310，抽 `![名](路径)` markdown 图，贴纸就这么发）+ 附件图块反查原图（host.js:524-526），本地图读成 base64，`http(s)://` 直接交 URL；正文 `按段拆()`（host.js:417，40 字气泡上限）按 `打字间隔()`（host.js:443，`min(6000, 220+n*55)` ms）逐条 `send_private_msg` / `send_group_msg`，图片随后发（段间 450ms）。
6. 每次调 OneBot 都带 `认证头()`（host.js:361，口令非空时 `Authorization: Bearer`）。

### 3.3 QQ → DSH（QQ 说话 → 伙伴）

**两条收路**：

- **WS 直连（主路）**：`连WS()`（host.js:1519）连 `WS地址`（默认 ws://127.0.0.1:3001）；`处理WS事件()`（host.js:1490）只认 `post_type==='message'`，按 `message_id` 去重进 `已转消息`，然后 `进批()`。断线 5 秒重连（host.js:1541），连接期间 HTTP 轮询自动补漏（推送处理过会推高 `上次私聊时间`，host.js:1504，轮询就不会重复转）。
- **HTTP 轮询（兜底）**：`ctx.interval` 每 1000ms 跑 `轮询收消息()`（host.js:1106）+ `提醒挂起消息()`（host.js:1416）。轮询拉 `get_friend_msg_history`（count 10）/ `get_group_msg_history`（count 30），按 `time >= 上次时间` + `message_id` 去重，只认 `私聊QQ` 这个人（自己的回话不会自我繁殖），空消息（纯表情已含在图里）跳过，然后同样 `进批()`。

**凑批 → 转进**：

1. `进批()`（host.js:1183）：消息进 `批缓冲`，新消息重置静默计时；等待 = `min(消息防抖窗口3000, 回合上限30000 - 首条年龄)`。
2. 到点跑 `转一批()`（host.js:1199）——**所有收消息路径的统一漏斗**：
   - **手机模式检查**（0.4.7 起，host.js:1207-1253）：`问手机()`（host.js:605，GET MuMu 控制口 /state）+ `手机在玩()`（host.js:625，`mode.active` 或 `playing`——后者兜住"喊停后模式关了她那回合还在玩"）。在玩时：命中暂停关键词（`命中暂停`，host.js:686）→ `结束手机(pause=true)`，模拟器不关，回执"我先放下"；命中停手（`命中停手`，host.js:668）→ `结束手机()`关模拟器 + 把主人原话 `agent.steer()` 进她正在跑的回合让她自己决定收不收（0.4.9，host.js:1231-1238）；否则（`忙时入队` 开 + agent running）→ `挂起消息()`（POST 控制口 /pending，host.js:632）+ `发挂起回执()`（host.js:721，冷却 `挂起回执冷却秒` 秒内只回一次）。
   - **长回合保护**（0.4.6，host.js:1257-1263）：回合中且 `本轮开始时间 > 0` 且已跑 ≥ `长回合保护60000` → 不取消，消息留在缓冲，等 turn/end 的冲刷口（host.js:808-816）再转。
   - 回合中但回合年轻（<60s）→ `agent.cancel({kind:'user'}, {keepInbox:true})` 取消旧回合（host.js:1276），新旧消息合并重开一轮。
   - 闲着 → 直接转出。
3. `转入一条()`（host.js:975）：收图（`取图字节` host.js:198 支持三种形态：url/file/base64://；限量 `收图最多`、限重 `图上限MB`；`看图类()` host.js:188 按魔数辨类型；`存一张()` 存 `~/.dsh/qq-bridge-inbox/`），拼文案"（称呼发了 N 张图：…要发回去就用 <路径>）"，图经 `attachments.admitPromptContent` 交给 DSH；成功后 `记收图()`（host.js:158）记"附件 id / 只读副本路径 → 原图"两张键（`~/.dsh/qq-bridge-received.json`，只留 200 条——DSH 归一化副本会把 GIF 变静态 webp，回发时先查这张表换回原图）。
   - 手机模式的暂停/停手/挂起也在这里再判一遍（host.js:1034-1077，覆盖 /receive 直调路径）。
   - 最后 **`await agent.followup(...)`（host.js:1082，⚠ 必须 await：不接住的 rejection 会让整个 DSH 宿主退出，0.2.0 的教训）**，兜底记 `本轮开始时间`，`sessions.flush`。
4. 手搓的用户消息形状（`手搓用户消息`，host.js:871）：`{ id, role:'user', content:[{type:'text',text}], source:{kind:'qq'} }`——不冒充她亲手打的。

### 3.4 超时汇报提醒（0.5.0–0.5.2）

`turn/start`（host.js:766）起 60 秒（`回合汇报阈值`，host.js:1175）定时器；触发时若总开关/目标会话正常、agent 还 `running`、`本轮已吭声` 为 false → `agent.steer(手搓用户消息('系统提示：…先立刻用 mumu_phone_say 发一句 10 字以内汇报…'))`（host.js:785）。**0.5.2 的关键修正**（host.js:750-757）：只有「给主人看的正文/图」才算吭声（`提取净正文` 非空 **或** `提取图块` 非空）；纯工具调用步（assistant/message 只带 tool_use）**不算**——否则她一调工具就把提醒撤了，提醒永远不发。回合结束/她吭声就撤定时器。

### 3.5 挂起消息提醒（她闲了）

`提醒挂起消息()`（host.js:1416，随 1 秒轮询跑）：她 `idle` 且 MuMu 控制口 /pending 有东西 → 只提醒**没提醒过的**（`已提醒过的` Set；同一批不反复送，0.3.9 的坑）；没新消息时 30 分钟兜底提一次（host.js:1442）；提醒文案带每条 `id=xxx「内容」`（她可直接 `mumu_phone_say(msg_id=…)` 回）；提完顺手 POST `/pending/handled` 标掉（host.js:1461-1473）。

### 3.6 系统提示过滤

DSH 会把运行时元信息（`Time sampled…`、`Elapsed since…`、`Current runtime context.` 等）作为文本块附进 assistant 消息。`是系统提示文字()`（host.js:267）**只认块首命中特征正则**（host.js:270），`提取净正文()`（host.js:274）把它们滤掉——她正文里引用这些词不会被误杀。

**热生效机制**：`读配置()`（host.js:233）每次被调都重读文件 + 归一化——事件处理、路由、WS 事件、超时提醒全是现读的。所以直接改这个 JSON 一般立即生效。例外：**WS 连接参数改了要重启 DSH**（`连WS()` 只在插件加载时跑，host.js:1548）。设置页保存走 `/save`（host.js:960，合并旧配置→归一化→写文件）。

### 3.8 设置页路由与双前缀

`apply(ctx)`（host.js:332）里 `路线()`（host.js:921）注册路由：**每条同时注册两个前缀**——新 `/dsh-qq-bridge/*` 和旧 `/dsh-qq-bridge-mumu/*`（host.js:922-939）。原因（0.5.1）：0.4.5 只把 host 的注册前缀从旧改新，但已发布的 client.js 请求仍走旧前缀 `B = '/dsh-qq-bridge-mumu'`（client.js:18）→ 全 404，设置页永远"读取中…"。修法选择双前缀兜底而不是改 client.js——已发布的设置页和文档里到处是旧路径，两条都通最稳。

### 3.9 mumu-mcp（手机那半边）

独立 python MCP stdio server（`mumu-mcp/server.py` 手写 JSON-RPC），DSH 挂载后工具名 `mcp__mumu__mumu_phone_*`（21 个工具，见 mumu-mcp/README.md）。与桥的配合点：

- **控制口 8791**：GET /state（`playing`/`forced`/pending）、POST /pending、POST /pending/handled、POST /exit（`pause=true` 不关机）。桥只跟控制口打交道，不直连 adb。
- 她回消息走 `mumu_phone_say` → 桥的 `/say` 直发 QQ 并自动标已处理。
- 配置在 `~/.dsh/mumu-mcp/config.json`（改它要重启 DSH，因为是 DSH spawn 的）。装了 dsh-mumu-up 唤醒器就别开 `autoplay_enable`，两套调度会重复叫她。

## 七、已知坑与陷阱（全部踩过）

1. **`agent.followup()` 必须 await**：不接住的 rejection 会变成未处理 rejection，**整个 DSH 宿主退出**（host.js:1079-1082 有注释；0.2.0 修）。任何新加的 followup/steer 调用都要 try/catch 包住。
2. **含长中文串的文件别用 sed / 中文 old_string edit 匹配**——不可见字符差异导致匹配失败或表达式炸。用 edit 工具（复制粘贴原文）或写 node 脚本改。
3. **工具调用步 ≠ 吭声**（0.5.2 的教训）：任何"收到 assistant/message 就撤销某状态"的逻辑，必须先看 `提取净正文` 非空**或有图**；她玩手机/查东西时回合里几乎全是 tool_use 步。
4. **路由改名要全链路对齐，或干脆双前缀兜底**（0.5.1 的教训）：host 注册、client 请求、README/文档示例三处。现在 `路线()` 每条路由双前缀，client.js 永远走旧前缀 `/dsh-qq-bridge-mumu`——别"顺手统一"删掉旧前缀。
5. **改插件必须重启 DSH**（插件启动时加载）。改配置 JSON 一般热生效，但 WS 连接参数、mumu-mcp 配置（DSH spawn 的）要重启。
6. **README 说配置文件是 `qq-bridge-mumu-config.json`，代码实际读 `qq-bridge-config.json`**（host.js:26）。以代码为准；README 未同步是已知文档债。
7. **DSH 归一化副本会毁动图**：GIF 经 DSH 存图变成静态 webp。所以收图时记"附件 id + 只读副本路径 → 原图"两张键（host.js:158），回发先反查（host.js:507、525）。伙伴照抄副本路径是常见情况，只按附件 id 认会漏。
8. **手机模式"在玩"要看两个信号**（host.js:625）：只看 `mode.active` 会漏"主人喊停后模式关了、她那回合还在玩"的情况——`playing`（3 分钟内动过手机）兜住。收消息检查必须留在 `转一批()` 漏斗里，别绕开（0.4.7 教训）。
9. **暂停关键词要先于停手判**：`"暂停一下"` 含 `"停一下"`，顺序反了暂停会被当收手（host.js:1039 注释）。停手匹配要求整句相等或词长 ≥3 才做包含，避免误伤"停下来"（host.js:678-681）。
10. **挂起消息只提醒一次**（0.3.9 的坑）：提醒本身不算"已处理"的话，同一批消息能重投一下午。现在提醒完 POST `/pending/handled` 标掉，老消息 30 分钟兜底一次。
11. **超时提醒的 steer 文案开头写"系统提示："**——她把它当系统级指示而不是主人的话。改动时保留这个形状。
12. **`ctx.interval` 拿不到时轮询跑不起来但 DSH→QQ 照常**（host.js:1396-1399 有兜底）；旧版 DSH 没有这个注入。
13. **cordis.patch.yml 手维护**：别跑会重排 yaml 的 setup 脚本（吞注释）。
14. **重启 DSH 的 pwsh 命令偶尔被中断且结果未知**——重查端口 + `/state` 版本再决定是否重跑，别盲目重跑（杀进程有竞态）。
15. **`已转消息` / `已发轮` / 收图表都设了上限防无限涨**（300 条 / 200 条，host.js:170、568、1164）——新增缓存记得照做。
